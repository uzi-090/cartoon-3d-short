# Manual voiceover handoff and sound

## The user supplies narration

After the script is agreed, request an audio file recorded by the user or generated by the user with their chosen AI voice service. MP3, WAV and M4A are useful inputs. **Wait for the file before frame-accurate animation.** Do not make a placeholder TTS voice into the final narrator or assume ElevenLabs/API access. For a missing or unreadable file, explain what is missing and wait for a usable copy.

Once supplied, copy it byte-for-byte into the project's private `voice/` folder. Inspect duration, channels, sample rate and clipping using ffprobe/FFmpeg or equivalent tools; listen when playback is actually available. A transcript and waveform are not evidence of subjective listening. Record the source hash in project state so later steps can verify preservation.

## Timing

Transcribe with word times using an available local tool or a user-authorized service. Avoid uploading a private recording to a service merely because transcription is needed. A local `faster-whisper` setup is one option. Correct names, omissions, punctuation, word starts/ends and the final spoken phrase by inspecting/listening to ambiguous areas.

Store timings in seconds from the beginning of the original recording, for example:

```json
[{"text":"He","start":0.18,"end":0.33},{"text":"waited.","start":0.34,"end":0.86}]
```

Derive animation and captions from those times. Use the recording's real pauses and delivery; don't force a borrowed word rate or stretch it to an arbitrary duration. A short visual ending may extend beyond speech if it earns its time.

## Mixing

Keep the original narration as the reference stem at its original pace. No hidden time stretch, pitch shift, rewrite or substitution. Establish baseline voice gain, then duck an original or licensed music bed and purposeful Foley under it. Don't blindly reuse a prior project's relative dB adjustments as absolute settings. Document intentional gain/EQ changes and any user-requested edits.

Use quiet space and silence intentionally. Sound can confirm a contact, reveal or shift in expectation; avoid a constant layer of generic whooshes. Match SFX to actual picture timing, including any later edits. Keep an event cue table so the mix can be regenerated when timing changes.

Render an exact-length mix at a suitable delivery rate such as 48 kHz. Check the final file for clipping, relative speech clarity, alignment, first/last words and music tails. A codec can add a few padding samples; distinguish that from an actual sync or truncation problem. Loudness and true-peak measurements support, but do not replace, playback review.

In the starter set `src/project.ts`'s `narrationFile` to a supplied file inside `public/`, `mixFile` to an optional reviewed mix, and `durationInFrames` from the timeline. Leave `mixFile` null to render the supplied recording directly. The source voice remains private and is not part of the public skill or default source distribution.
